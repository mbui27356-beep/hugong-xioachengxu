# 交付说明（阶段 B + C：无云原型与本地联动）

日期：2026-10-26。范围：小程序、管理后台、共用的本地 Node.js + TypeScript 后端。未接入真实云开发、微信支付与订阅消息。

## 1. 数据来源

小程序和管理后台现在使用**同一个数据源**：本地后端 `backend/`，数据保存在 `backend/data/db.json`。

- 原先两端各自有独立 Mock（小程序 `wx.Storage`、后台 `localStorage`），彼此不同步。两份 Mock 已删除。
- 所有计价、状态变更、权限与范围校验都在后端执行，两端只负责收集输入和展示结果。
- 后台的接口类型直接取自后端实现（`admin-web/src/services/*.ts`），两边签名不一致时无法通过编译。小程序 DTO 来自 `packages/contracts/customer.ts`。

## 2. 测试结果

### 2.1 自动化联动验收：63 / 63 通过

运行 `npm --prefix backend run test:e2e`。脚本会启动一个独立后端（使用临时数据文件），调用两端实际使用的同一组 HTTP 接口，最后把结果写入 `backend/tests/last-run.json`。

| 分组 | 验证内容 |
|---|---|
| 目录维护 | 城市、区县、医院、院区、科室、病区、套餐的新增、编辑、停用与上下架，都能在小程序重新加载后反映；跨院区挂病区被阻止 |
| 提交预约 | 报价由服务端计算，忽略客户端传来的单价；未确认全部协议、代约未确认同意时拒绝提交；后台看到同一笔订单，含地点、套餐、价格快照、评估、床位与代填关系，敏感资料默认脱敏 |
| 确认 → 待支付 | 待确认时不能支付；用过期版本号确认会被拒绝；确认后小程序变为待支付，并收到通知 |
| 支付 → 待服务 | 模拟渠道回调入账；重复支付不会重复入账；两端都显示待服务、已支付 |
| 派单与履约 | 未派单时不能开始服务；结束服务必须填写完成凭据；小程序依次显示护工、服务中、已完成和完整时间线 |
| 站内消息 | 后台按订单发送后小程序未读数 +1，阅读后减少；其他账号收不到 |
| 取消与退款 | 待确认、待支付订单可取消，支付单随之关闭；已支付订单需走售后；退款按“申请 → 核定 → 执行 → 失败 → 重试”流转，重试复用同一单号；超出可退额度被拒绝；后台取消已付款订单时自动生成退款申请，退款未完成不显示“已退款” |
| 关键异常 | 后台改价后历史订单价格不变，调价前的报价不能下单；下架后不能报价、不能下单；伪造跨医院组合被拒绝；提前量不足、负数天数、评估未完成、错误电话都有提示；用户 B 无法查看或操作用户 A 的订单、就诊人与消息；调度员不能越过医院范围；财务不能确认订单；内部函数与模拟支付不能从正式接口调用 |
| 重启保留 | 重启后端后订单、新医院与消息仍在；重启后重放同一请求号仍返回原订单 |
| 关闭演示模式 | `DEMO_MODE=off` 时模拟支付与演示身份接口均不可用 |

6. 后台“消息管理”发送「服务回访」，小程序消息列表显示该消息，标签栏出现未读角标，阅读后未读数 8 → 7。

8. 小程序切换到演示用户 02，看不到用户 01 的订单与消息。
9. 重启本地后端后，以上数据仍在。

测试中发现并已修复：订单完成后小程序与后台列表不再显示护工；后台“科室管理”页加载时报错（变量在声明前使用）。

## 3. 仍为模拟的功能（集中封装，生产不可用）

| 能力 | 位置 | 生产保护 |
|---|---|---|
| 小程序登录身份 | 后端 `adapters/mock/identity.ts`；小程序 `services/demo.ts` 通过请求头 `x-demo-user` 传递 | 小程序 `config.ts` 中 `DEMO=false` 时不发送该请求头 |
| 后台登录身份 | 后端 `adapters/mock/identity.ts`；后台 `services/demoIdentity.ts` 通过 `x-demo-admin` 传递，右上角可切换角色 | 身份切换接口 `session.*` 只在演示模式注册 |
| 微信支付 | 后端 `adapters/mock/payment.ts`（模拟下单、渠道状态、查单）与 `modules/demo`（模拟收银台付款，接口 `/api/demo/pay`）；小程序 `services/demo.ts` 中的 `mockCashier` / `mockPay` | 只在演示模式注册；`NODE_ENV=production` 且开启演示模式时后端拒绝启动；小程序 `DEMO=false` 时 `services/payment.ts` 不会走模拟路径 |
| 退款渠道 | 后台执行退款时直接返回成功或模拟失败 | 需替换为真实退款接口与退款回调 |
| 数据库 | `repositories/jsonFileStore.ts`：单个 JSON 文件，整份写入 | 仅适合单进程本地联调 |
| 演示工具 | 后台“系统设置 → 演示工具”（重置数据、模拟网络失败）、订单抽屉“模拟他人修改” | 需从生产构建中移除 |
